Read and follow the [shared workflow contract](../setup/references/workflow.md), including its setup entry check and any active unattended delivery mode. In full-send/full-stop, record blockers without asking or waiting for the absent user. Resolve task artifacts from `docs/sdlc/project.md`.

# Babysit a pull request

Resolve the PR, target branch, current head, intended scope, accepted artifacts, required checks, review policy, and merge authorization. A request to take this PR through merge authorizes merge once the agreed gates pass. A request only to fix or review it does not. A user request to run this review loop authorizes its review-trigger comments, including `@codex review`, unless the user explicitly restricts that communication. Preserve existing authorization; do not ask again after it is given.

Make the most minimal possible changes to appease the reviewers. Be careful of scope creep and don't be scared to push back. Evaluate each request against the accepted task and evidence; fix concrete defects, and explain why an invalid or out-of-scope request should not change this PR.

Inspect the PR body/diff, check runs, review decisions, issue comments, review comments, unresolved threads, and mergeability. Use the actual remote state; local success and old bot reactions do not establish current readiness. Preserve unrelated work using an isolated worktree where needed. If the current head has neither a completed required review nor a pending request for one, request that review using the same authorization and deduplication rules below before waiting. Apply this on entry and whenever the remote head changes.

Repeat until the requested endpoint; one review round is not completion:

1. Classify failed checks and findings. Reproduce actionable findings; fix the smallest correct layer. For an invalid or out-of-scope finding, record evidence and use the repository's resolution process. Do not weaken a test, quality threshold, or review policy to clear the gate.
2. Run the relevant local checks, update execution evidence, commit and push the scoped fix. Resolve threads only after their disposition is supported. After every push, including conflict fixes and rebases, request a fresh review of the new remote head. For Codex review, post `@codex review` once for that head after the push; reuse an already pending request for the same head. Post review-trigger comments only when the user has authorized this communication; otherwise expose that specific remaining gate. Local review does not replace a required remote review.
3. Wait for that review and required CI. Poll current checks, threads, review results, and merge state with a moderate cadence (30-60 seconds unless otherwise requested). Keep the user informed. A pending check or review stays pending; silence or a clean review of an older head is not a completed clean review of this head. An acknowledgement or reaction counts only if the configured reviewer contract establishes it as a completed clean review for this head. Skipped/neutral checks count only when the agreed policy explicitly permits them.
4. If the reviewer returns findings, evaluate them and repeat the fix, verification, push, and fresh-review cycle. For Codex, require a completed review reporting “no major issues” or the configured equivalent clean completion signal on the current head. Keep a short record of reviewed heads, findings, dispositions, and evidence in `execution.md` to distinguish new defects from repeated requests.
5. Detect review loops and scope creep: the same finding returns despite a verified fix or evidence-backed rebuttal, requests contradict earlier rounds, or the reviewer asks for unrelated behavior or a broader redesign. Push back with the accepted scope and concrete evidence through authorized review communication. Continue independent in-scope work, but if the disagreement cannot be resolved within scope, stop with the disputed findings and the decision needed to proceed. Ask only in interactive runs; unattended modes save the blocker and end without questions. A loop or scope dispute is not a clean review and does not authorize merge.
6. Handle upstream conflicts by inspecting both sides and preserving the accepted behavior. Re-run affected checks and review after integration; do not blindly choose either side. Any resulting push starts another review cycle.
7. At the requested endpoint, refresh the live head, base, checks, approvals, threads, and mergeability. Verify the current head matches the checked and reviewed head, required checks and approvals pass, blocking threads are resolved, and the accepted scope remains intact. When merge is authorized, merge through the repository's normal protected path with an expected-head guard when available. Never bypass gates.

After merge, verify the remote PR reports merged and its merge commit is on the target branch. Handle squash/rebase semantics without requiring the original branch commit to be an ancestor. Report PR URL and merge commit. Verify deployment only if deployment was included in the request.

If merge is not authorized, hand off the open, unmerged PR with its final head and ready-to-merge verdict once the same gates pass. If only required human approval remains, report that actual blocker separately; do not call it ready. A requested stop before merge is a completed handoff, without another merge permission prompt. If an external gate is unavailable, a new material decision is needed, or the same failure persists after three distinct attempted fixes, save the current head, evidence, blocker, and next action in `execution.md`; report the obstacle rather than looping indefinitely. Ordinary pending CI is not a failed fix attempt. Resume by refreshing remote state and these receipts, not replaying prior actions.
